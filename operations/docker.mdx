AgentOS runs several Docker containers for services that benefit from isolation: the Paperclip control plane, LiteLLM model routing, Neo4j knowledge graph storage, an embeddings server, and the Graphiti entity extraction pipeline. All containers have explicit memory limits to prevent host OOM cascades.

<Warning>
LiteLLM and Paperclip both run in Docker. If the Docker daemon crashes, all model routing and issue management go down — causing mass agent failures across all companies. The health daemon monitors Docker and auto-restarts it when possible.
</Warning>

<Note>
AgentOS migrated from macOS (node name: Lauryn) to a cloud VPS (Debian 13, kernel 6.8.0-117). Docker service paths and configurations reflect the VPS deployment. The old macOS-specific launchd services are no longer used.
</Note>

## Container inventory

### Paperclip stack

**Compose file**: `/docker/paperclip-ezk7/docker-compose.yml`

| Container | Image | Port | Memory | Purpose |
|-----------|-------|------|--------|---------|
| `paperclip` | `paperclip:2026.517.0` | 3100 | — | Paperclip control plane (issue tracker, agent dispatch, plugins) |
| `paperclip-db` | `postgres:16` | 54329 | — | PostgreSQL database for Paperclip |

<Note>
The Paperclip PostgreSQL instance runs on port **54329** (not the default 5432) to avoid host conflicts. The database uses `SQL_ASCII` encoding — no Unicode in string fields.
</Note>

### LiteLLM stack

| Container | Image | Port | Memory | Purpose |
|-----------|-------|------|--------|---------|
| `litellm-proxy` | `ghcr.io/berriai/litellm:main-latest` | 4000 | 2 GB | Model routing proxy |

### Hermes gateway (s6-overlay container)

**Compose file**: `/paperclip/repos/hermes/docker-compose.yml`

| Container | Image | Port | Memory | Purpose |
|-----------|-------|------|--------|---------|
| `hermes` | `hermes-agent` (local build) | — | — | Hermes gateway (s6-overlay supervised, `network_mode: host`) |
| `hermes-dashboard` | `hermes-agent` (local build) | 9119 (localhost only) | — | Hermes dashboard (localhost-only, API key management) |

<Warning>
The Hermes dashboard binds to `127.0.0.1:9119` only. It stores API keys — exposing it on LAN without auth is unsafe. For remote access, use an SSH tunnel (`ssh -L 9119:localhost:9119`). Do NOT run it with `--host 0.0.0.0` unless behind an authenticated reverse proxy.
</Warning>

## Managing Docker services

## Patches mechanism

The OpenClaw gateway applies approximately 78 targeted patches on top of the upstream `main` branch. Patches live in the `/patches/` directory and are applied by `/patches/apply-patches-docker.sh` during container build. This keeps upstream sync easy while adding features like priority lanes, task panels, and circuit breakers.

## Automatic disk pruning

The health daemon's `docker_prune` subsystem automatically prunes Docker when disk usage hits 80%. A 12-hour cooldown between prunes prevents aggressive churn.

## Removed: Langfuse stack

Langfuse was self-hosted until **2026-04-26**, when it migrated to Langfuse Cloud (`us.cloud.langfuse.com`). The migration eliminated 5 containers and approximately 30 GB of disk usage:

- Langfuse web
- Langfuse worker
- Clickhouse
- MinIO
- Redis

The old configuration is preserved (commented out) in `~/.litellm/docker-compose.yml` for rollback reference.

## Removed: macOS launchd services

The following macOS-specific services no longer run after the cloud VPS migration:

- `ai.openclaw.gateway` — launchd-managed gateway (now s6-overlay in Docker)
- `ai.openclaw.gateway-2` — second gateway (now single gateway in container)
- `ai.openclaw.healthd` — health daemon (now s6 supervised)
- All other launchd plists for OpenClaw

Service lifecycle is now managed entirely by Docker Compose and the s6-overlay supervision tree inside the Hermes container.
