AgentOS is a multi-agent platform built on [OpenClaw](https://github.com/openclaw/openclaw) that runs Chris Abad's businesses autonomously. It orchestrates **30 AI agents** across **7 companies**, handling everything from infrastructure maintenance to content creation to financial reporting. This documentation serves both humans navigating the system and agents making decisions within it.

## How it all connects

The diagram below shows the full request path — from inbound message to completed work:

```text
Slack / Webhooks
    ↓
OpenClaw Gateway (Node.js)
    ↓ agent binding + triage routing
LiteLLM Proxy (Docker, port 4000)
    ↓ semantic model → provider routing
Ollama Cloud / Claude OAuth / Gemini / GPT
    ↑ tool calls + responses
Agent → tools (exec, Read/Write, memory, message)
    ↓
Paperclip (issue tracker) ←→ Issue Trigger Plugin ←→ Reed (dispatcher)
    ↓
Implementer agents pick up issues → execute → review → close
```

## Key principles

These rules govern how every agent in the system behaves. Understanding them prevents most mistakes.

1. **Agents escalate to Juno, not Chris.** Juno is the sole Slack interface to Chris. All other agents communicate via Paperclip comments.
2. **Paperclip is the work system.** Issues are how work gets tracked, assigned, and reviewed. Not Slack threads, not Linear tickets for infra work.
3. **Config changes go through `openclaw-schema.json`.** Never edit `openclaw.json` directly — it's generated. Use `openclaw config set` to apply.
4. **Maintenance windows are enforced.** Gateway restarts and config builds happen 2–4 AM PT only, unless Juno approves an exception.
5. **Self-healing over manual intervention.** Every infra fix should close the class of failure, not just the instance.
