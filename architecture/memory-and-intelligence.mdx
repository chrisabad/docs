AgentOS gives agents both short-term session context and long-term knowledge through a multi-layered memory system. When an agent calls `memory_search`, it gets results that span recent session transcripts, curated workspace facts, and a continuously updated knowledge graph — all through a single interface.

## Architecture

```text
┌──────────────────────────────────────────────────┐
│                 Agent Session                     │
│  memory_search tool → hybrid retrieval           │
└──────────┬──────────────────────┬────────────────┘
           │                      │
┌──────────▼──────────┐  ┌───────▼────────────────┐
│  Session Transcripts │  │  Workspace Memory      │
│  JSONL per agent     │  │  Markdown files         │
│  Indexed by embeddings│  │  Curated durable facts │
└──────────┬──────────┘  └────────────────────────┘
           │
┌──────────▼──────────────────────────────────────┐
│           Embedding Server (port 8001)           │
│           Gemma-300M GGUF, 768-dim              │

           │
┌──────────▼──────────────────────────────────────┐
│           Graphiti Knowledge Graph               │
│           Neo4j + Graphiti overlay               │
│           Fed by Intelligence Connectors         │
└─────────────────────────────────────────────────┘
```

## Layer 1: Session transcripts

Every agent session is recorded as a JSONL file at `~/.openclaw/agents/<id>/sessions/`. These are the raw conversation logs — tool calls, model responses, and user messages.

The `memory_search` tool queries these transcripts using:

- **Embedding similarity** via the local Gemma-300M model (port 8001)
- **Temporal decay** — recent sessions are weighted higher than older ones
- **Hybrid MMR** — Maximal Marginal Relevance to avoid redundant results

Session archives are pruned automatically by the `session-archive` launchd job, with retention configured per agent.

## Layer 3: Intelligence pipeline

External data sources are continuously ingested into the knowledge graph through four Python connectors at `~/.openclaw/intelligence-pipeline/connectors/`:

| Connector | Launchd plist | Schedule | Source |
|-----------|--------------|----------|--------|
| `calendar-connector.py` | `ai.openclaw.intel-calendar` | 8:00 + 18:00 daily | Google Calendar |
| `email-connector.py` | `ai.openclaw.intel-email` | Continuous | Gmail |
| `granola-connector.py` | `ai.openclaw.intel-granola` | Continuous | Granola meeting transcripts |
| `slack-connector.py` | `ai.openclaw.intel-slack` | Every 30 minutes | Slack channels (WEE config) |

### Embedding server

A Docker container at port 8001 runs a Gemma-300M GGUF model for local embeddings. It produces 768-dimensional vectors and exposes an OpenAI-compatible API at `/v1/embeddings`.

### Graphiti knowledge graph

A Docker stack provides the graph backend:

- **Neo4j** (port 7474/7687) — Graph database, 1.8 GB RAM
- **Graphiti overlay** (port 8000) — `zepai/graphiti:latest` — handles entity extraction, relationship mapping, and temporal reasoning
- Uses the LiteLLM proxy on host:4000 with `fast`/`routine` models during entity extraction

<Note>
Agents don't directly query the knowledge graph. Graphiti results are surfaced through the same `memory_search` interface as session transcripts.
</Note>

## Layer 4: Claude Code memory (Juno-specific)

Juno's Claude Code harness maintains its own memory at `/Users/openclaw/.claude/projects/-Users-openclaw/memory/`:

| File pattern | Purpose |
|-------------|---------|
| `MEMORY.md` | Index of all memory entries |

| `project_*.md` | Project state snapshots |

This memory persists across Juno's Claude Code conversations and is separate from the workspace memory.

## How agents use memory

When an agent needs context, it calls `memory_search` with a natural language query. The system processes it in order:

<Steps>
  <Step title="Embed the query">
    The query is embedded via the local Gemma-300M model on port 8001.
  </Step>
  <Step title="Search session transcripts">
    Transcript JSONL files are searched by embedding similarity.
  </Step>
  <Step title="Apply temporal decay">
    Recent sessions are scored higher than older ones.
  </Step>
  <Step title="Diversify with MMR">
    Maximal Marginal Relevance removes redundant passages from results.
  </Step>
  <Step title="Return top-k passages">
    The most relevant, diverse passages are returned to the agent.
  </Step>
</Steps>

## Wiki

A structured wiki lives at `~/.openclaw/wiki/main/`:

- `index.md`, `inbox.md` — Entry points
- `concepts/`, `entities/`, `syntheses/`, `reports/` — Organized knowledge
- `sources/imports/` — Imported content

The wiki serves as a longer-form knowledge base that agents can reference for background context on entities, decisions, and system concepts.
