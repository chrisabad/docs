The AGE (AgentOS Infrastructure) company runs the platform itself. These agents keep every other agent functioning: routing work, reviewing code, monitoring health, auditing behavior, and diagnosing failures. None of the business-unit agents in FON, WEE, PIX, KAL, DIA, or STU could operate without them.

<Note>
All agents run via the `hermes_local` adapter inside the Hermes Docker container. Agent profiles live at `/opt/hermes-profiles/<name>/config.yaml`. Model routing uses `provider: auto`, which resolves through the Hermes gateway to the cheapest available provider. Agent instructions (AGENTS.md) are stored at `/docker/paperclip-ezk7/data/agent-instructions/<name>/AGENTS.md`.
</Note>

  <Accordion title="Quinn — QA / code reviewer">

    Quinn is the **QA / Code Reviewer** for AGE. Every completed issue passes through Quinn before it can be marked `done`.

    | Field | Value |
    |-------|-------|
    | **Hermes profile** | `/opt/hermes-profiles/quinn/` |
    | **Paperclip UUID** | `67f1e093-3020-488a-ad18-cbe6658376ea` |
    | **Model** | `glm-5.1` via `provider: auto` |
    | **Adapter** | `hermes_local` |
    | **Wake pattern** | Paperclip `wakeOnDemand` — auto-assigned to `in_review` issues by the issue-trigger plugin |
    | **WIP cap** | 1 |
    | **Reports to** | Juno |

    **How the review cycle works:**

    1. An implementer (Axel, Ellis, etc.) moves an issue to `in_review`
    2. The issue-trigger plugin auto-assigns Quinn
    3. Quinn wakes and runs verification commands from the proof-of-work comment
    4. If verification passes → Quinn moves the issue to `done` (PASS)
    5. If verification fails → Quinn moves it back to `in_progress` (FAIL/REJECT) with feedback

    **Key rules:**
    - Headless — Paperclip only, no Slack
    - PASS detection prevents review loops: the issue-trigger plugin checks for a recent PASS verdict before allowing `done` status
    - Quinn rejection auto-assigns the original implementer via the issue-trigger plugin
