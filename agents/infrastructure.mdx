The AGE (AgentOS Infrastructure) company runs the platform itself. These eight agents keep every other agent functioning: routing work, reviewing code, monitoring health, auditing behavior, and diagnosing failures. None of the business-unit agents in FON, WEE, PIX, KAL, DIA, or STU could operate without them.

  <Accordion title="Reed — Cross-company dispatcher">

    Reed is the **cross-company queue dispatcher**. It doesn't execute work — it makes sure the right agent picks up the right issue at the right time.

    | Field | Value |
    |-------|-------|
    | **OpenClaw ID** | `reed` |
    | **Workspace** | `agents/dispatch/` |
    | **Model** | `litellm/routine` (fallback: `litellm/fast-weekend`) |
    | **Wake pattern** | `wakeOnDemand` — wakes when issues are created or assigned |
    | **Reports to** | Juno |

    **The 10-sweep queue protocol:** On every wake, Reed runs a sequential sweep across the relevant company.

    | Sweep | Action |
    |-------|--------|
    | 1. Triage | Assign unassigned `todo`/`backlog` issues to the correct agent based on domain signals |
    | 2. Backlog promotion | Move eligible `backlog` → `todo` based on WIP headroom and priority |
    | 3. Stale detection | Flag `in_progress` issues older than 48 h with a nudge comment |
    | 4. Duplicate detection | Find and block duplicate issues |
    | 5. Dependency validation | Validate dependency labels after auto-unblock |
    | 6. Failed run release | Auto-release issues with failed runs (3 retries → escalate to Juno) |
    | 7. Stale blocked escalation | Detect `blocked:external` issues stuck too long |
    | 8. Cold queue recovery | Re-queue issues for agents with heartbeats >5 min old |
    | 9. Plugin health check | Auto-heal missing plugins |
    | 10. Blocked reconciliation | Un-block issues that should be unblocked |

    **Domain signal routing (AGE example):**

    | Signal keywords | Assigned agent |
    |----------------|---------------|
    | Gateway, proxy, LiteLLM, config, patches | Axel |
    | Heartbeat, scheduling, Paperclip, Slack, onboarding | Ellis |
    | Health checks, observability, monitoring | Orion |
    | Strategy, escalation, ambiguous | Juno |

    Each company has its own routing table in `~/.openclaw/workspace/agents/dispatch/AGENTS.md`. The `$PAPERCLIP_COMPANY_ID` environment variable determines which company Reed sweeps on each wake. Reed operates across all 7 companies: AGE, WEE, FON, KAL, DIA, PIX, STU.

    **Key rules:**
    - Reed routes — it never executes implementation work
    - Reed enforces WIP caps and won't assign to an agent at their limit
    - Cold queue recovery: if an agent's heartbeat is >5 min stale, Reed unassigns their issues and re-queues them
    - 3 run failures triggers escalation to Juno instead of another retry

  <Accordion title="Quinn — QA / code reviewer">

    Quinn is the **QA / Code Reviewer** for AGE. Every completed issue passes through Quinn before it can be marked `done`.

    | Field | Value |
    |-------|-------|
    | **OpenClaw ID** | `quinn` |
    | **Paperclip UUID** | `334294f1-2e21-47ab-86ec-aed0487c9a7d` |
    | **Model** | `litellm/pro` |
    | **Wake pattern** | Paperclip `wakeOnDemand` — auto-assigned to `in_review` issues by the issue-trigger plugin |
    | **WIP cap** | 2 |
    | **Reports to** | Juno |

    **How the review cycle works:**

    1. An implementer (Axel, Ellis, etc.) moves an issue to `in_review`
    2. The issue-trigger plugin auto-assigns Quinn
    3. Quinn wakes and runs verification commands from the proof-of-work comment
    4. If verification passes → Quinn moves the issue to `done` (PASS)
    5. If verification fails → Quinn moves it back to `in_progress` (FAIL/REJECT) with feedback

    **Key rules:**
    - Headless — Paperclip only, no Slack
    - PASS detection prevents review loops: the issue-trigger plugin checks for a recent PASS verdict before allowing `done` status
    - Quinn rejection auto-assigns the original implementer via the issue-trigger plugin

  </Accordion>
